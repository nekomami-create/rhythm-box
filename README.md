# BreakBox

16 ステップのステップシーケンサーで、ドラムを打ち込み、**和音（コード）とベースとリード**を重ねて曲に組み立てる Android アプリです。
音源ファイルは持たず、**すべての音をアプリ内で合成**しています（サンプル素材の同梱・ダウンロード不要）。

## ダウンロード

**[BreakBox.apk をダウンロード](https://github.com/nekomami-create/rhythm-box/releases/download/rhythmbox-latest/BreakBox.apk)**
（このリンクはいつも最新版を指します。[リリース一覧](https://github.com/nekomami-create/rhythm-box/releases) からバージョンを選ぶこともできます）

### インストール

1. 上のリンクから APK をダウンロードする
2. 開こうとすると「提供元不明のアプリ」の確認が出るので、この操作を許可する
3. インストールして開く

- **Android 8.0 (API 26) 以上**が必要です
- Google Play では配布していません。APK を直接入れる形です
- 更新は**上書きインストールするだけ**です。アンインストールは不要で、保存した曲もそのまま残ります
- 広告・課金・通信は一切ありません。音はすべて端末の中で作っています

## 主な機能

- **16 ステップ x 8 音色**のドラム打ち込み（BD / SD / CH / OH / CP / RS / TM / CB）
- **コード（和音）**: 小節ごとにコードを指定。12 ルート x 8 種類（maj / m / 7 / m7 / M7 / sus4 / dim / aug）
  - コードとベースはドラムと同じ 16 ステップの行で「いつ鳴らすか」を打ち込む。**音の高さはその小節のコードから決まる**ので、コードを変えるだけで同じパターンが違う響きになります
- **リード（単音の旋律）**: 別タブのピアノロール（C4〜C6）で 1 ステップ 1 音を打ち込み。**自動生成**もできます
  （拍の頭はコードの構成音、動きは順次進行を優先するので、調から外れた旋律にはなりません）
  - 旋律は**繰り返しごとに別々に持てます**。ドラムは 4 小節同じでも、旋律は小節ごとのコードに合わせて変えられます
- **コードのおすすめ**: 曲に出てくるコードから調を推定し、**前後の小節に馴染むコード**を度数つきで提案
  （V → I、IV → V、vi → ii など、よくある進行の重みで並べ替え。両隣が分かっているときは
  「前から来やすく、次へ繋がりやすい」ものを上位にします）
- **8 小節つくる**: ジャンルを選ぶ（またはおまかせ）だけで、テンポ・コード進行・リズムを決めて
  「A を 4 小節 + B を 4 小節」の曲をまるごと作ります
- **オート作曲**: ジャンルと長さ（4〜64 小節）を選ぶだけで、テンポ・コード進行・リズム・旋律を決めて曲をまるごと作ります
- **ジャンルから作る**: ロック / J-POP / バラード / シティポップ / ダンス を選ぶと、
  テンポ・コード進行（王道進行・小室進行・カノン進行・丸サ進行など）・リズム・旋律をまとめて設定します
- **起承転結でコード進行を自動生成**: 曲を 4 つに区切り、起（調を示す）承（広げる）転（主和音から離れる）結（帰る）
  の役割で埋めます。**最後の数小節だけを終止形（結）に差し替える**こともできます
- **リズムの自動生成**: ボタン 1 つでパターンを生成。8ビート / 4つ打ち / ブレイクビーツ / ヒップホップ / ラテン
  の 5 スタイル + おまかせ。気に入らなければ「戻す」で 1 つ前に戻せます
- **音声の書き出し**: 曲・チェーン・パターンを **M4A (AAC)** ファイルに書き出し（保存先は SAF で自由に選択）
- **ヘルプ**: 使い方をアプリ内のヘルプタブにまとめています
- **テンポ (40〜240 BPM)** とマスター音量、11 トラック（ドラム 8 + コード / ベース / リード）の音量・ミュート
- **パターン A〜H** の切り替え・クリア・コピー（パターンごとに試聴用のコードを持ちます）
- **3 つの再生の仕方**
  - パターン: 選んでいるパターン 1 小節をループ（打ち込みながら聴く用。常にループします）
  - **チェーン**: 中身のあるパターンを A→B→C… と 1 小節ずつ繋げて再生。曲構成を作らずに流して聴けます
  - 曲: 曲構成を通しで再生
  チェーンと曲のループは画面右上のループボタンで切り替え（既定はオン）。
  再生ボタンの下に「チェーン A→B→C をループ」のように今の状態が出ます
- **曲構成**: パターンを「A を 4 小節 → B を 2 小節…」と並べ、**小節ごとにコードを指定**して通し再生
- **自動保存 + 複数曲の管理**（新規作成・複製・名前変更・切り替え・削除）
- 再生中もその場で打ち込み・コードを変更できる（音は止まりません）
- 再生位置は実際に鳴っている音に合わせて表示（AudioTrack の再生位置を参照）
- トラック名や鍵盤をタップすると、その音だけを単発で試聴

## 使い方

1. 上部の **パターン** タブでグリッドをタップして打ち込み、▶ でループ再生。
   下 2 行（CHD / BAS）がコードとベースです。「コード」ボタンでこのパターンの和音を決められます。
2. **リード** タブのピアノロールで旋律を足す（同じマスをもう一度押すと消えます）。
3. 何も思いつかないときは「ランダム」でリズムを生成 → 気に入るまで押す →「戻す」で 1 つ前に復帰。
   複数のパターンができたら「チェーン A→B→C」で繋げて流せます（鳴っているパターンのボタンが光ります）。
4. パターン A〜H を切り替えて、いくつかのパターンを作る（「コピー」で複製してから変えると早いです）。
5. **曲構成** タブで「パターンを追加」→ 並び順と繰り返し小節数を指定 → 各行の下のコードボタンで小節ごとの和音を決める → ▶ で通し再生。
   コードを押すと「つぎに合うコード」が出るので、そこから選ぶだけでも進行になります。「コード進行おまかせ」で全小節を一気に埋めることも。
6. 編集内容は自動保存されます。曲の切り替えや新規作成は右上の ⋮ メニューから。

## 技術スタック

- Kotlin / Jetpack Compose (Material 3)
- 音声出力: `AudioTrack`（32bit float・モノラル・ストリーミング）
- 書き出し: `MediaCodec` (AAC LC 128kbps) + `MediaMuxer`（M4A）。外部ライブラリなし
- 音源: 自前のシンセ（ドラムは作り置きの波形、コード / ベース / リードはその場で加算合成）
- 保存: kotlinx.serialization による JSON ファイル（`filesDir/songs.json`）

### モジュール構成

Android に依存する部分としない部分を分けています。`:core` は JVM 単体テストで検証できます。

```
core/   … 音源合成・シーケンサ・データモデル（純 Kotlin）
  Model.kt          パターン / コード / 曲 / ミキサー設定
  DrumSynth.kt      ドラム 8 音色のワンショット波形を合成
  ToneSynth.kt      コード / ベース / リードの音色（倍音構成と ADSR）
  ChordSuggester.kt 調の推定と「つぎに合うコード」、コード進行の自動生成
  PatternGenerator.kt リズムパターンの自動生成（スタイル別）
  MelodyGenerator.kt リードの自動生成（調とコードに沿った旋律）
  Genre.kt          ジャンルのプリセットと、定番コード進行の型
  OfflineRenderer.kt 書き出し用に、実時間を待たず一気にレンダリング
  PlaybackPlan.kt   「どの小節でどのパターンをどのコードで鳴らすか」（1 小節ループ / チェーン / 曲構成）
  PlaybackEngine.kt ステップ発音・発振器・ミックス・ソフトリミッタ
  StepTimeline.kt   再生位置の履歴（表示を音に合わせる）
  SongCodec.kt      JSON の読み書きと値の補正

app/    … Android アプリ（Compose UI / AudioTrack / ファイル保存）
  audio/AudioOutput.kt     AudioTrack への書き込みスレッド
  audio/AacEncoder.kt      MediaCodec + MediaMuxer で M4A に圧縮
  audio/AudioExporter.kt   レンダリング → 圧縮 → 保存先へコピー
  data/SongRepository.kt   自動保存つきの曲リポジトリ
  ui/                      画面（パターン / リード / 曲構成 / ヘルプ）・ViewModel・テーマ
```

## 開発者向け

Android Studio (Ladybug 以降推奨) でプロジェクトを開くか、コマンドラインから:

```bash
./gradlew :core:test           # 音源・シーケンサの単体テスト
./gradlew testDebugUnitTest    # アプリ側の単体テスト
./gradlew assembleDebug        # 開発用 APK をビルド
./gradlew assembleRelease      # 配布用 APK をビルド
```

- **compileSdk / targetSdk**: 35
- **minSdk**: 26 (Android 8.0)

Android SDK のパスは `local.properties` に `sdk.dir=/path/to/Android/sdk` として設定するか、
`ANDROID_HOME` 環境変数で指定してください（このファイルは Git 管理外）。

### 配布のしかた

GitHub Actions (`.github/workflows/android.yml`) が単体テストと **release ビルド**を行い、
GitHub Release に `BreakBox.apk` を公開します（Actions の成果物ストレージ枠を消費しないため、
Release のアセットとして置いています）。

- **main への push** … `rhythmbox-latest` タグのローリングリリースを更新。ダウンロード URL は不変
- **`v1.2.3` のようなタグを push** … そのバージョンで固定のリリースを作成（変更履歴は自動生成）

バージョンを切るときは、`app/build.gradle.kts` の `versionCode` / `versionName` を上げてから
同じ番号のタグを押してください。

```bash
git tag v1.9.0 && git push origin v1.9.0
```

配布用ビルドは `app/debug.keystore` の固定鍵で署名しています。デバッグビルドと同じ鍵なので、
**これまで入れた APK に上書き更新できます**（署名が変わると更新できず、保存データが消えます）。
R8 での圧縮は実機で確認できていないため切ってあります。

> [!NOTE]
> 署名鍵 (`app/debug.keystore`, パスワード `android`) はリポジトリに置いてあります。
> 誰でも同じ鍵で署名できるので、Google Play で配布する場合は必ず別の鍵に差し替えてください。
> ここでは「上書き更新でデータが消えないこと」を優先しています。

## 自動生成のしくみ

**コードのおすすめ** — まず曲に出てくるコードから調を推定します（24 通りの調について、音階に収まるコードの数で採点し、
最初と最後のコードが主和音になる調を優先）。そのうえで、機能和声のよくある進行を 7x7 の重みの表にしてあり、
今のコードの度数から次の度数を重み順に並べます。メジャーキーでは V7、マイナーキーでは和声的短音階の V（メジャー）も候補に足します。
進行の自動生成は、曲を起承転結の 4 区間に割り、区間ごとの「その度数の使いやすさ」と進行の重みを掛けて選びます
（転では主和音の重みを 0.05 まで落とし、平坦にならないようにしています）。
終止形（結）は型を用意してあり、3 小節以上なら最後の 1 つ前が必ず V（ドミナント）になります。
マイナーキーでは V をメジャーにして（和声的短音階）終止感を強めています。
曲の途中の小節を選び直すときは、前の小節から来る重みと次の小節へ向かう重みの相乗平均を取り、
片側だけに馴染む候補が上に来ないようにしています（C → ? → G なら F が最有力、C → ? → C なら G）。

**旋律の生成** — 使う音は調の音階の中だけに限り、拍の頭ではコードの構成音に着地させます。
音の選び方は「直前の音に近いほど選ばれやすい」重み付けで、跳躍は時々しか起きません（1 オクターブを超える跳躍はしない）。
リズムは決まった型から 1 つ選び、拍の頭以外を少しだけ抜いて変化を付けています。

**ジャンル** — ジャンルらしさの大半は、ドラムパターンではなくコード進行とテンポから来ています
（特に J-POP はドラムだけではほぼ判別できません）。そのため「ジャンル」はドラムの型ではなく、
テンポ・リズム・コード進行・旋律の密度をまとめて設定するプリセットとして持たせています。
コード進行は確率で組み立てるのではなく定番の型をそのまま使います。
王道進行の `V → iii` は遷移の重みが 0.20 しかなく、確率で作るとまず出てこないためです。

**リズムの生成** — 完全な乱数だと音楽になりません。スタイルごとに「必ず置く位置」（キックの 1 拍目、スネアの 2・4 拍目など）を決め、
細かいところだけを確率で揺らします。ハイハットは確率で置くとランダムに穴が空いて雑に聞こえるので、
4 分 / 8 分 / 8 分裏 / 16 分の刻みを丸ごと 1 つ選んでから飾りを足す形にしています。

## 音づくりのメモ

- キック: サイン波のピッチを 141Hz → 46Hz へ一気に落とし、頭にノイズのクリックを重ねる
- スネア: 186Hz / 331Hz のサイン波 + ハイパスしたノイズ
- ハイハット: 6 本の矩形波を非整数倍で重ねてハイパス（減衰時間だけ変えてクローズド／オープン）
- クラップ: 10ms 間隔のノイズバースト 3 連発 + 残響
- コード: 整数倍の倍音を薄く重ねたドローバーオルガン風。ルートが F# 以上のコードは 1 オクターブ下げて、
  進行しても音の高さが飛び跳ねないようにしています
- ベース: 低次倍音だけの丸い音。リードは奇数倍音だけの矩形波寄りの音
- 音の長さは「次に同じ行が鳴るまで」。コードは小節いっぱい、ベースとリードは最長 4 ステップで切ります
- 同時に鳴った音が歪まないよう、出力の直前でソフトリミッタを通しています
- クローズドハットはオープンハットを止めます（実機と同じ挙動）

## 書き出しについて

書き出しは再生と同じ [`PlaybackEngine`](core/src/main/kotlin/com/example/rhythmbox/core/PlaybackEngine.kt) を
そのまま使い、実時間を待たずに一気に描いています（別経路で作り直すと、聴いている音と書き出した音がズレるため）。
曲の終わりのあとも 2 秒ぶん描き続けるので、最後のシンバルやコードの余韻が途切れません。

MP3 ではなく M4A (AAC) にしているのは、Android 標準の `MediaCodec` だけで完結するためです。
MP3 で書き出すには LAME を NDK で組み込む必要があり、ビルド環境と APK サイズの負担が増えます。
M4A は MP3 と同程度に小さく、スマホ・PC・DAW のいずれでもそのまま再生できます。

## 名前について

アプリ名は **BreakBox** ですが、パッケージ名は `com.example.rhythmbox` のままにしてあります。
パッケージ名を変えると Android は別アプリとして扱い、保存した曲が消えてしまうためです。
リポジトリ名とリリースのタグ (`rhythmbox-latest`) も、既存のリンクを壊さないようそのままです。
